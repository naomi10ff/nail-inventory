# ネイルサロン在庫管理システム

複数店舗(生駒店・西大寺宝来店・木津店)のジェル在庫を、スマホのバーコード/QRスキャンで
棚卸できるようにする最小構成のシステムです。データベースはGoogleスプレッドシート、
バックエンドはGoogle Apps Script(GAS)、フロントエンドはスマホブラウザで開く静的HTMLページです。

- 商品マスタの新規登録・修正・削除、入荷登録、廃棄登録は本社アカウントのみ行えます
  (店舗を選んで操作する)。店舗アカウントは棚卸・在庫情報の閲覧・在庫検索のみ行えます
- 店舗アカウントは自店のデータしか閲覧できません(他店舗のデータには一切アクセス不可)
- 3店舗合算の総在庫・欠品一覧は本社アカウントのみ閲覧できます
- 本社アカウントにも「在庫検索」があり、店舗を選んでバーコードをスキャンすると、その
  店舗の最新在庫を確認できます(店舗アカウントの在庫検索は自店固定、本社は店舗を選べる
  点が異なります)
- 在庫のリセット(個別・一括)は取り消せない操作のため、実行前に本社パスワードの再入力と
  警告表示を必須にしており、ワンクリックでは実行できません
- 「総在庫・欠品一覧」の各商品には「修正」ボタンがあり、入荷登録の入力ミスやシステムの
  不具合などで実際と違う数になった在庫を、本社パスワードの再入力とともに正しい数へ直接
  書き換えられます(種別「調整」として記録され、棚卸承認画面の棚卸実施回数には数えません)
- 在庫情報はCSV形式でエクスポートでき、Excel/Googleスプレッドシートで開けます
- 商品マスタには「コード」(スキャン用のバーコード、無ければ自動発行のQR)と「品番」
  (発注時にメーカー/問屋に伝える商品コード)の両方を別々に登録できます。同じ商品でも
  バーコードが読めない・付いていないことがありますが、品番は仕入れ先のカタログ上に
  常に存在するため分けています
- 商品マスタには「メモ」欄があり、同じ商品なのにバーコードが違う場合の注釈などに使えます
- 「マスタ整理(表記ゆれ)」画面では、店舗を選んで「重複候補を探す」を押すと、大文字/
  小文字や全角/半角、スペースの有無だけが違う同じブランド名(例:「BELLA FORMA」と
  「BellaForma」)を自動で見つけて、選んだ表記に一括で統一できます。品名の表記ゆれ候補も
  一覧表示されますが、こちらは自動統一しません(本当に同じ商品とは限らないため)。確認の
  うえ商品管理画面の「編集」「削除」で対応してください
- 商品マスタの編集画面では、コード自体も書き換えられます。バーコードが無い商品を先に
  品名・ブランドだけ登録しておき(コード欄は空欄で自動発行)、後で見つかった実物の
  バーコードに差し替える、という使い方を想定しています。ただし取引ログ(棚卸・入荷・
  廃棄の履歴)は変更前のコードのまま残るため、既に履歴がある商品のコードは変更しないで
  ください(現在庫の計算が新しいコードの履歴なしからやり直しになります)
- 棚卸は「確定」を押すとすぐには送信されず、その店舗の登録商品のうちまだスキャンして
  いないものが一覧表示されます。それを確認したうえで「本社へ送信する」を押すと送信されます
  (スキャン漏れの確認用)
- 本社の「棚卸承認」画面では、店舗・対象月を選ぶと「先月末在庫+今月の入荷−今月の廃棄」と
  「今月末在庫(棚卸後)」を商品ごとに突き合わせて差異を確認できます。内容を確認して
  「承認する」を押すと、確認済みの記録(承認者・日時)が残ります(データの修正・削除自体は
  制限しません)。店舗アカウントからも「棚卸承認の確認」画面で同じ内容と承認状況を閲覧できます
  (承認操作自体は本社のみ)

## 構成

```
gas/            Google Apps Script(バックエンド・データベース連携)
  appsscript.json
  Sheets.gs     シート初期化(初回に1回だけ実行)
  Auth.gs       ログイン認証・セッション・アカウント管理
  Code.gs       APIエンドポイント(doGet/doPost)・在庫集計ロジック
  Backup.gs     スプレッドシート全体の自動バックアップ(日次トリガー)
web/            スマホブラウザで開く静的ページ(店舗用・本社用は1つのURLに統一済み)
  index.html    エントリーポイント(ログインしたアカウントの権限で店舗用/本社用に自動振り分け)
  app.js        店舗用・本社用の両方のロジックをまとめたスクリプト
  shared/       共通CSS
```

## セットアップ手順

### 1. スプレッドシートとApps Scriptプロジェクトを作成

1. Googleドライブで新規スプレッドシートを作成(例:「ネイルサロン在庫管理」)
2. メニューの `拡張機能 > Apps Script` を開く
3. デフォルトの `コード.gs` を削除し、このリポジトリの `gas/` フォルダ内のファイルを
   同じファイル名でコピー&ペーストして追加する(`appsscript.json` は「プロジェクトの設定」で
   「`appsscript.json` マニフェストファイルをエディタで表示する」を有効にすると編集できます)
4. エディタ上部の関数選択で `setupSpreadsheet` を選び、実行する
   - 初回実行時にスプレッドシートへのアクセス許可を求められるので許可する
   - 実行ログ(表示 > ログ)に初期アカウントのユーザー名・仮パスワードが出力されるので必ず控える
   - この関数はシートの雛形と初期アカウントを作成する。既にアカウントが存在する場合は
     アカウントを上書きしないので、再実行しても安全
5. `Backup.gs` を開いた状態で `setupDailyBackupTrigger` を選び、実行する
   - Googleドライブへのアクセス許可を求められるので許可する
   - 毎日深夜3時(日本時間)に、スプレッドシート全体のバックアップがGoogleドライブの
     「在庫管理バックアップ」フォルダに自動保存されるようになる(30日より古いものは自動削除)

### 2. Web Appとしてデプロイ

1. 右上の「デプロイ」>「新しいデプロイ」を選択
2. 種類の選択で「ウェブアプリ」を選ぶ
3. 「実行するユーザー」は自分、「アクセスできるユーザー」は「全員」に設定してデプロイ
4. 発行されたウェブアプリのURL(`https://script.google.com/macros/s/.../exec`)を控える

### 3. フロントエンドにAPI URLを設定

`web/app.js` の先頭にある

```js
const CONFIG = {
  API_URL: 'REPLACE_WITH_YOUR_WEB_APP_URL'
};
```

の `REPLACE_WITH_YOUR_WEB_APP_URL` を、手順2で控えたURLに差し替える。

### 4. 静的ページを公開する

`web/` フォルダをスマホから開けるどこかにホスティングする。候補:

- **GitHub Pages**(無料・推奨):このリポジトリをGitHubにpushし、Pagesを有効化
- **Firebase Hosting**:`firebase deploy` で静的ファイルを配信
- 動作確認だけなら、PC上で `python -m http.server` を実行し、スマホを同じWi-Fiに繋いで
  `http://<PCのIPアドレス>:8000/web/` を開く(この方法は社内テスト用。カメラ利用には
  HTTPSが必要なブラウザもあるため、本番運用はHTTPS配信のホスティングを利用してください)

公開後、店舗スタッフにも本社担当者にも同じ **`.../web/` のURL** を共有する。ログインした
アカウントの権限(店舗/本社)に応じて、表示される画面が自動的に振り分けられる。

> 以前あった店舗用・本社用別々のURL(`.../web/store/`・`.../web/hq/`)は統合版への
> 切り替えが完了したため廃止し、`web/store/`・`web/hq/` フォルダ自体を削除した。

### 5. 初期データを投入する

1. `.../web/` に本社アカウントでログイン(手順1で控えた `hq / change-me-hq` )
2. 「アカウント」画面で、必ず本社パスワードをリセットしてから、3店舗分の店舗アカウントの
   パスワードもリセットする(初期パスワードは `change-me-1` 〜 `change-me-3` )
3. 「入荷登録」画面で店舗を選び、扱っているジェルのバーコードをスキャン(または手入力)
   すると、未登録の商品はその場で品名・ブランドなどを入力して登録できる。バーコードが
   無い商品は、同じ画面の「バーコード無しの商品を新規登録」からスキャンせずに登録でき、
   自動でQRコードが発行されるので印刷して現物に貼る。ブランド名・カテゴリーは選択時に
   新しい名前を入力すると自動で候補に追加される。「商品管理」画面では新規登録は行わず、
   検索・編集・QRコードの表示/まとめて印刷・削除のみ扱う。商品マスタの登録・修正・削除は
   本社アカウントのみ行える
4. 「スタッフ」画面で、各店舗のスタッフ名を登録する

### ホーム画面にアイコンを追加する(任意)

毎回ブラウザでURLを開く手間を省くため、スマホのホーム画面にアイコンを追加できます。

**Androidの場合**
1. ブラウザ(Chrome)でいつものURLを開く
2. 右上の「⋮」(縦三点リーダー)をタップ
3. 「ホーム画面に追加」を選んでタップ

**iPhoneの場合**
1. ブラウザ(Safari)でいつものURLを開く
2. 下部の共有ボタン(四角から矢印が出ているアイコン)をタップ
3. 「ホーム画面に追加」を選んでタップ

追加後はアイコンをタップするだけで、URLバーの無い全画面のアプリのように開きます。

## 動作確認の進め方

カメラでのバーコード/QRスキャンは端末・ブラウザ(特にiOS Safari)によって挙動が変わることが
あるため、まず本社アカウントと店舗アカウント1つずつで以下の順に通しで確認することを推奨します。

1. 本社アカウントでログイン →「入荷登録」で店舗を選び、テスト用のバーコードをスキャン
   (または手入力)して、未登録商品として品名等を入力し登録する。「バーコード無しの商品を
   新規登録」からQRコードを発行するパターンも試す
2. 発行したQRコードを印刷し、別の端末やスマホでスキャンして正しく商品が読み取れること
3. 「入荷登録」で店舗を選び、手順1で登録済みのバーコード/QRをスキャンして入荷を登録できる
   こと。別の未登録バーコードをスキャンした場合は、その場で品名等を入力して商品登録し、
   続けて入荷登録できること
4. 「破棄登録」で同じ店舗を選び、同じ商品をスキャンして現在庫が表示されること。廃棄本数を
   入力して確定すると在庫が減ること
5. 店舗アカウントでログイン → スタッフ名を選択できること
6. 「棚卸」で複数商品を連続スキャンし、ブランドごとに集計されること、「確定」で送信されること
7. 「在庫情報」で自店の在庫が正しく表示されること(手順3・4の入荷・廃棄が反映されていること)
8. 「在庫検索」でバーコードをスキャンし、自店の最新在庫が確認できること
9. 別の店舗アカウントでログインし、他店舗のデータが一切見えない・操作できないことを確認
10. 本社アカウントでログインし、3店舗合算・店舗別内訳・欠品一覧が見えること
11. 本社アカウントで取引ログの削除、商品マスタの削除ができること
12. 「在庫情報」の検索欄で、全角/半角・大文字/小文字・カタカナ/ひらがなの違う表記でも
    同じ商品がヒットすること、スペース区切りの複数キーワードで絞り込めること
13. 「在庫情報」「店舗別在庫一覧」でCSVエクスポートし、Excel/Googleスプレッドシートで
    文字化けなく開けること
14. 本社アカウントで商品を1件リセットし、パスワードを間違えると失敗すること、正しいパスワード
    で実行すると在庫が0になること
15. 本社アカウントで店舗を絞り込んだ状態と「全店舗」の状態、それぞれで一括リセットを実行し、
    意図した範囲だけが0になることを確認する(取り消せない操作なのでテスト用データで確認する)

いずれもスプレッドシートの `取引ログ` シートに行が追記されることも合わせて確認してください。
`現在庫サマリ` シートは入荷登録・廃棄登録では自動更新されません(理由は次項)。

## 既にスプレッドシートを運用中の場合の移行手順

### 自動バックアップの追加(新機能)

スプレッドシート全体を、毎日深夜3時にGoogleドライブの「在庫管理バックアップ」フォルダへ
日付付きでコピーする仕組みを追加しました(30日より古いものは自動削除されます)。
Googleスプレッドシートの変更履歴だけでは、ファイル自体の誤削除などには備えられないため、
別ファイルとしてのバックアップを用意しています。設定手順:

1. `gas/Backup.gs` の内容を、Apps Scriptエディタに新しいファイルとして追加する
   (ファイル名は `Backup.gs` のままでOK)
2. `gas/appsscript.json` を最新の内容に置き換える(Googleドライブへのアクセス権限が
   追加されています)
3. `Backup.gs` を開いた状態で、関数選択から `setupDailyBackupTrigger` を選んで実行する
   (初回はGoogleドライブへのアクセス許可を求められるので許可する)
4. 実行ログに「毎日深夜3時(日本時間)に自動でバックアップするよう設定しました。」と
   出れば設定完了。以降は何もしなくても毎日自動でバックアップされる
5. 今すぐ1回バックアップを取りたい場合は、同じファイルから `backupSpreadsheet` を
   直接実行してもよい

### 商品マスタへの「品番」列の追加(破壊的変更なし)

商品マスタに、発注時に使う「品番」列を追加しました(スキャン用の「コード」とは別物)。
Apps Scriptエディタから `Sheets.gs` の `setupSpreadsheet()` を**再実行**してください。
既存の行・列には一切触れず、ヘッダーに「品番」が無ければ最後尾に列を追加するだけです。
既存商品の品番は空欄になるので、必要な商品だけ商品管理画面の編集から追記してください。

### 「カテゴリマスタ」シートの追加(破壊的変更なし)

カテゴリー(ベース/トップ・カラー・その他・物販)を全店舗共通のマスタとして管理する
ようにしました。ブランドと同様、商品登録・編集時に新しいカテゴリー名を入力すると
自動で追加されます。Apps Scriptエディタから `Sheets.gs` の `setupSpreadsheet()` を
**再実行**してください。既存のシート・データには一切触れず、`カテゴリマスタ` シートが
無ければ既定のカテゴリー(ベース/トップ・カラー・その他・物販)付きで新規作成されるだけです。

### 「棚卸承認」シートの追加(破壊的変更なし)

棚卸承認の記録用に新しいシート `棚卸承認` を追加しました。Apps Scriptエディタから
`Sheets.gs` の `setupSpreadsheet()` を**再実行**してください。既存のシート・データには
一切触れず、`棚卸承認` シートが無ければ新規作成されるだけです(既存アカウント等も
上書きされません。詳しくは各シート初期化処理の実装を参照)。

### 商品マスタ・ブランドマスタの店舗別管理化(破壊的な移行)

商品マスタ・ブランドマスタを、全店舗共有の1つのリストから「店舗ごとに独立したリスト」に
変更しました(先頭に「店舗」列を追加)。この変更は既存の列構成と互換性が無いため、
`Sheets.gs` に追加した `migrateToPerStoreMasters()` を **Apps Scriptエディタから手動で1回**
実行してください。

**この関数を実行すると、`商品マスタ`・`ブランドマスタ`・`取引ログ`・`現在庫サマリ` の中身は
すべて削除され、新しい列構成のヘッダーだけが書き直されます。** アカウント・スタッフマスタ・
セッションは消えません。実行前に、残しておきたいデータがないか必ず確認してください。

実行後は、各店舗ごとに商品マスタ・ブランドを登録し直す必要があります(本社の「商品管理」
画面で店舗を選んで登録できます)。

### 商品マスタに「カラーNO」列、新規シート「ブランドマスタ」を追加(上記より前の変更)

上記の店舗別管理化を行うのであれば、下記の手順は不要です(`migrateToPerStoreMasters()` が
まとめて新しい列構成にしてくれます)。

## 既知の制約・注意点

- GASのWeb Appはpreflight(CORSのOPTIONSリクエスト)に対応していないため、フロントエンドは
  リクエストの `Content-Type` を `text/plain` にして単純リクエストとして送信しています。
  独自にAPIを拡張する際もこの制約に注意してください。
- 「現在庫」は、直近の棚卸カウントを基準に、それ以降の入荷(+)・廃棄(−)を加減算して
  算出しています。棚卸を実施するたびに実カウントへリセットされるため、紛失や記録漏れによる
  ズレはその都度補正されます。
- セッション(ログイン状態)は30日間有効です。スタッフ入れ替え時などでセッションを無効化
  したい場合は、スプレッドシートの `セッション` シートから該当行を削除してください。
- `現在庫サマリ` シートは、アプリの画面表示では使っていません(画面は毎回 `取引ログ` から
  直接集計しています)。スプレッドシート上で在庫を直接見たい人向けの参考シートで、以前は
  入荷登録・廃棄登録のたびに自動更新していましたが、取引ログが増えるほどこの更新処理が
  重くなり登録の体感速度に直結していたため、自動更新をやめました。最新化したい場合は
  Apps Scriptエディタから `refreshCurrentStockSummary()` を手動実行してください
  (商品マスタの編集・在庫リセットなど、頻度の低い操作では引き続き自動更新されます)。
